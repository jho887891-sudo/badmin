# 07 — 三级调整 Spec

## 1. 总原则

失败后严格按：

```text
一级：局部调整
→ 复测
→ 证据证明仍不足
→ 二级：中局调整
→ 复测
→ 证据证明仍存在结构性瓶颈
→ 三级：模型框架调整
```

禁止跳级。

每一级都必须：

```text
记录修改
→ 原固定测试协议复测
→ 有效则保留
→ 无效则回退
```

# 2. Level 1 — 局部调整

## 2.1 目标

不改变当前模型总体结构。

## 2.2 可调整内容

### 数据

- 补某个像素尺寸桶；
- 补某三维姿态；
- 补运动模糊；
- 补遮挡；
- 补真实数据；
- 增加 hard negatives；
- 修标签；
- 去重；
- 调整合成 / 真实比例。

### 训练

- 学习率；
- batch；
- epoch；
- 数据增强；
- loss 权重；
- freeze / unfreeze；
- sampler；
- 样本权重。

### 推理

- confidence threshold；
- IoU threshold；
- Top-K；
- 后处理规则。

## 2.3 典型因果链

```text
6–8 px Recall 低
→ 检查发现该尺寸真实样本不足
→ 模型缺乏该分布训练
→ 补同尺寸真实/合成样本
→ 重训
→ 原 6–8 px 固定测试复测
```

## 2.4 进入 Level 2 的门

必须证明：

```text
数据覆盖充分
+ 标签已验证
+ 针对性训练已经执行
+ 阈值工作点已经扫描
+ 固定测试仍不达标
```

# 3. Level 2 — 中局调整

## 3.1 目标

保留基本检测框架，但允许改变输入和训练组织方式。

## 3.2 输入分辨率

比较例如：

- 640
- 960
- 1280

准确因果链：

```text
输入分辨率提高
→ 同一羽毛球在网络输入中保留更多像素
→ 更细局部视觉结构进入网络
→ 小目标 Recall 可能提高
→ 同时计算量、延迟和显存增加
```

必须同时测：

- Recall
- temporal continuity
- latency
- VRAM

## 3.3 ROI / Crop

只有系统存在可靠先验区域时允许。

```text
可靠 ROI
→ 裁剪后同一羽毛球占输入更大比例
→ 减少全图缩放导致的信息损失
```

## 3.4 训练组织

允许比较：

- weighted sampling
- difficult-example oversampling
- curriculum learning
- synthetic-heavy → balanced → real-heavy
- 分阶段 freeze / unfreeze

每一种调整必须用固定核心测试集对比。

## 3.5 进入 Level 3 的门

必须有证据：

```text
Level 1 已排除主要数据/参数问题
+
Level 2 已比较输入和训练组织
+
模型仍在明确条件下表现出持续结构性瓶颈
```

# 4. Level 3 — 大局调整

## 4.1 目标

允许改变模型结构或整体检测框架。

## 4.2 P2 检测分支

准确表述：

```text
增加 P2 检测分支
→ 检测头新增 stride=4 检测尺度
→ 更高分辨率特征直接进入检测头
→ 理论上能够保留更多极小目标空间信息
→ 是否提高羽毛球 Recall 必须实测
```

公平比较必须保持：

- 相同 train / val / test；
- 相同 seed；
- 相同 epoch；
- 相同输入分辨率；
- 相同优化器；
- 相同评价代码。

## 4.3 更换检测器结构

只有明确证据表明当前结构存在能力边界时允许。

判断标准不是“更先进”，而是：

```text
新结构针对已确认瓶颈提供不同检测机制
→ 在相同数据和评价协议下实测
→ 同时比较精度、连续性、延迟、显存
```

## 4.4 两阶段检测

```text
第一阶段找候选区域
→ 第二阶段高分辨率精检测
```

适用于：

```text
全图目标过小
→ 但候选区域可可靠缩小
```

必须计算额外延迟和流程复杂度。

## 4.5 多帧时序检测

只允许在：

```text
单帧静态能力已经基本满足
→ 但真实高速视频连续漏检仍明显
```

时进入。

准确因果链：

```text
单帧因模糊/极小而信息不足
→ 邻近帧仍包含相关空间和运动信息
→ 多帧融合利用时间冗余
→ 可能减少连续漏检
```

必须重点比较：

- longest miss streak
- reacquisition time
- latency

## 4.6 Level 3 替换条件

新框架只有同时满足：

```text
任务 Recall 更好
AND
视频连续性更好或至少不退化
AND
Precision 不明显恶化
AND
端到端延迟满足预算
AND
显存满足预算
```

才能替换原模型。

否则 `REVERT`。

## 5. 退出状态

调整后回到原测试协议复测。

满足系统要求 → 进入 Spec 08。

仍不满足 → 返回 Spec 06 重新诊断。
