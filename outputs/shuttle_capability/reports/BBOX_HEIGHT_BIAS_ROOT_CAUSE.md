### 0.1 一句话根因

**height_ratio ≈ 1.092 真实存在（预测框 vs val 标签），但它既不是坐标 / letterbox / 评估 bug，也不是「模型学了一个 1.092 的倍率」。**

1. **主因 = 标签规范不一致**：在**同一宽度桶**内，val 的 GT 框比 train 的系统性更扁（更矮）。以 eth_main（占 val 的 96% GT）为例，1024 输入系中位高度：
   - 宽度 [14,20)：train **13.27** px vs val **12.27** px（aspect 1.286 → 1.400）
   - 宽度 [20,28)：train **17.60** px vs val **15.47** px（aspect 1.323 → 1.483）
   - 宽度 [28,40)：train **23.34** px vs val **18.67** px（aspect 1.360 → 1.760）

   模型学的是 train 规范，于是在 val 上高度平均多预测 **+1.3 px（1024 系）**；对 8–16 px 目标即 **+9%～+11%**，与 1.092 吻合。
2. **叠加项 = aspect 回归到均值**：预测宽高比被压向 train 均值区（约 1.1–1.4）：GT aspect 0.677 → 预测 0.801；GT aspect 1.960 → 预测 1.521。于是扁框（aspect ≥ 1.4，占 TP 的 50%）高度 +1.5～+2.2 px，高框（aspect < 0.8）高度 −1.0 px。
3. **两个天然对照组**：与 train 规范一致的来源无此偏差 —— eth_iphone（aspect 0.91）h_ratio **1.020**、synthetic（aspect 0.90）h_ratio **1.015**；不一致的 eth_main h_ratio **1.095**。三个 checkpoint 一致（1.0919 / 1.0918 / 1.0936）。

### 0.3 不是固定倍率，也不是单纯 +1 px

- 1024 系下 pred_h − gt_h 的**众数 = +1.0 px**（28.5% TP），中位 +1.28，P10 −0.62、P90 +3.11；宽度众数 0.0、中位 +0.008（居中无系统偏差）。
- 但误差随尺寸 / 宽高比变化：按桶 h_ratio = 1.119 / 1.110 / 1.088 / 1.040 / **0.973** / 1.064 / **0.988**（4-6 / 8-12 / 12-16 / 16-24 / 24-32 / 32-64 / > 64）；dh 中位 = +0.70 / +1.38 / +1.33 / +1.13 / **−0.83** / +1.59 / **−4.66** px；按 aspect，dh 中位从 −1.02（aspect < 0.8）单调升到 **+2.24** px（aspect ≥ 1.7）。→ 正偏移集中在「扁且小」的目标，大目标反而偏矮。

## 1. 坐标路径与公式（逐行取自实际代码）

```
GT（本仓库评估器 tools/eval_yolo26_v1.py:401-402，无 letterbox、无 padding）:
    w_px = bw*W ; h_px = bh*H             # W,H = PIL Image.open(img).size
    box  = [(cx-bw/2)*W, (cy-bh/2)*H, (cx+bw/2)*W, (cy+bh/2)*H]

letterbox（ultralytics 8.4.150 data/augment.py, LetterBox）:
    r = min(imgsz/H, imgsz/W)              # 1745  同一个 r 用于 x 与 y
    new_unpad = (round(W*r), round(H*r))   # 1751
    dw,dh = imgsz-round(W*r), imgsz-round(H*r) ; dw/=2 ; dh/=2      # 1752,1761-1762
    top=round(dh-0.1) bottom=round(dh+0.1) left=round(dw-0.1) right=round(dw+0.1)  # 1764-1765
    img = cv2.resize(img, new_unpad) ; copyMakeBorder(top,bottom,left,right,114)   # 1793,1801
    boxes: denormalize(W,H) -> *ratio(r,r) -> +(left,top)                          # 1884-1886
    rect(auto=True) 仅在同形状批次且 args.rect 时启用；predict 默认关闭 -> 恒 1024x1024  # predictor.py:212-219

scale-back（models/yolo/detect/predict.py:121 -> utils/ops.py:146-165, ratio_pad=None）:
    gain = min(img1_h/H, img1_w/W) ; gain_y = gain_x = gain        # 147-148
    pad_x = round((img1_w-round(W*gain))/2-0.1) ; pad_y 同理     # 149-150
    x1-=pad_x y1-=pad_y x2-=pad_x y2-=pad_y ; /=gain ; clip_boxes # 155-165

本仓库评估器不自己解码预测：直接用 ultralytics 返回的 res.boxes.xyxy（已回代到原图）。
equiv_size_640 / center_err_px640 只用于分桶与展示，不参与 pred/GT 比值（比值恒在原始像素系）。
```

先验排除的两类原因：

- gain_x == gain_y（各向同性）：纯缩放/letterbox 误差会让 w 与 h 产生相同比例偏差，无法产生 w_ratio≈1.00 而 h_ratio≈1.09 的方向性模式。
- padding 只平移不改尺寸：pad 以相同方式进入 x1/y1/x2/y2，只影响中心误差。
- 唯一轴向不对称来自 new_unpad 取整：内容按 round(W*r)/W 与 round(H*r)/H 缩放、回代除以名义 r，残差 ≤0.5/(min(W,H)*r)，量级 ≤0.1%，方向偏小（见 2 节 T3）。

### 12.2 Q1–Q5

**Q1. height_ratio ≈ 1.092 是评估 bug 还是真实模型预测偏差？**
**真实偏差（预测 vs val 标签），不是评估 bug。** 坐标 / letterbox / scale-back / GT 解码 / matching 全部通过回环与 ultralytics 逐框一致性验证（最大差 0.0；缓存 vs 原生 ≤ 0.303 px），AP 口径与既有报告逐位一致。

**Q2. 若是真实偏差，主要来自哪一项？**
**标签规范（train/val 的框高与宽高比不一致）为主（CONFIRMED，解释平均正偏）**，**叠加 aspect 回归到均值（CONFIRMED，解释随尺寸/宽高比的形态）**；**小目标 1 px 量化只是 POSSIBLE 的次要成分**（众数 +1.0 px，但解释不了大目标负偏移）；**motion blur 不支持**。

**Q3. 对 AP75 / AP85 / AP90 / AP95 的影响分别多大？**
只纠正高度尺寸（保持中心与宽度，a_best）：AP75 +0.100、AP85 +0.217、AP90 +0.160、AP95 +0.034；若把该轴定位误差一并纠正：AP75 +0.177、AP85 +0.432、**AP90 +0.425**、**AP95 +0.194**。对照：只纠正宽度整轴 +0.198 / +0.409 / +0.355 / +0.133；只纠正 center +0.077 / +0.158 / +0.137 / +0.060。全部纠正（GT 框）上限 AP75/85/90/95 = 0.9184。

**Q4. center / width / height 谁对高 IoU 损失贡献最大？**
**并列首要：height 与 center；width 最小。** 干净归因（各自只改自己的量，其余保持）：AP90 = height **+0.160** > center **+0.137** > width **+0.070**；AP95 = center **+0.060** > height **+0.034** > width **+0.018**；AP75 / AP80 = height ≈ center > width。上一轮「center 不是主因」需修正为「center 与 height 并列」。

**Q5. 是否有足够证据支持下一阶段？**
- **A. 修 evaluator：不支持**（无 bug）。
- **B. 修数据 / 标签规范：证据最强（推荐优先）**。先查清同一 eth_main 下 train/val 标注规范差异的来源，再统一规范并重导 val（或重训时统一规范）；**本轮禁止改标签，只给方案不动手**。
- **C. 提高输入分辨率：POSSIBLE**。系统性正偏来自标签规范（提高分辨率不会消除），但 TP 宽度误差 P10/P90 = −3.27 / +2.20 px（1024 系）说明精度受输入粒度限制，且 8–16 px 目标在 imgsz=1024 时只跨 1–2 个 P3 网格；可作为**次要**手段单独评估。
- **D. Stage C（低 LR + Mosaic=0）：不支持作为本问题的解法**（无证据表明训练策略能消除 train/val 标注规范差异）；且纪律要求根因确认前不启动 Stage C —— 本轮只做判定，**不启动**。
- **E. 调整 box loss：不支持（无证据）**。改 loss 只会更贴合 train 规范，预期不降低 val 上的高度正偏。
