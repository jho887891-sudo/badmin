# Tiny-object Recovery V1 - evidence-chain post-mortem

> 2026-10-06｜实验 `ETH_HARDNEG_TINY_RECOVERY_V1`｜设计 `2026-10-05-tiny-object-recovery-v1-design.md`
> 本文件只复盘证据链与它支持/不支持什么，不重复实验报告（`tiny_recovery_v1_report.md`）的完整表格。

## 0. 结论（一句话）

本轮的证据链**强烈支持 representability / spatial-resolution bottleneck** 是 `<8 px` 目标的主导限制：在冻结的 imgsz=1024 下，
严格小于一个 P3 stride 的 43 个 tiny GT 在训练前后**没有任何被预测框重叠到（best IoU 恒为 0.0000）**，给它们多加暴露（<4 与 4-6 合计 +172 次）
也**没有产生任何新的检测响应**；而全部收益（4 -> 6 命中）都来自已经高于 stride 的 6-8 桶（+540 次暴露）。
这**不**是"实验注定失败"：它是对**决策边界假设**的一次正确检验，该假设在 6-8 桶上被弱支持、在 sub-stride 桶上被证伪。

## 2. 证据链（四段）

### 2.1 事前：失败集中在什么尺寸上

| 桶 | GT | V2 命中 | V2 recall | 1024 网络帧内中位尺寸 | 严格小于 1 个 stride(8 px) 的 GT |
|---|---|---|---|---|---|
| <4 | 24 | 0 | 0.0000 | 5.33 px | 24 / 24 |
| 4-6 | 37 | 0 | 0.0000 | 7.98 px | 19 / 37 |
| 6-8 | 44 | 4 | 0.0909 | 11.46 px | **0 / 44** |

换算口径：`net_px = equiv_size_640 x 1024/640 = 1.6 x equiv_size_640`；plain YOLO26s 的 P3 stride = 8 px。
两个 recall 恰为 0 的桶，正是尺寸落在 stride 数量级及以下的桶；唯一有命中的桶完全在 stride 之上。

### 2.2 事前：弱候选探针（conf >= 0.01、任意 IoU >= 0.1、不做贪心）

V2 的 101 个 tiny 漏检中只有 **5 个**存在任何候选框（4.95%）。

### 2.3 干预：剂量-反应（本轮新增，逐桶精确账）

| 桶 | V2 暴露 | 额外暴露 | 训练后暴露 | 命中变化 | 弱候选(>=0.1) 变化 |
|---|---|---|---|---|---|
| <4 | 161 | **+19** | 180 | 0 -> 0 | 0 -> 0 |
| 4-6 | 1,282 | **+153** | 1,435 | 0 -> 0 | 0 -> 1 |
| 6-8 | 4,522 | **+540** | 5,062 | **4 -> 6** | 9 -> 10 |

读法：把 +172 次暴露投给 sub-stride 的两个桶，换来**零命中**；把 +540 次投给 stride 之上的桶，换来 **+2 命中**。
付出与收益的方向完全取决于尺寸是否高于一个 stride，而不是取决于暴露总量。

### 2.4 事后：同一探针复跑（机制复核）

- tiny 漏检数 101 -> 99，但**有弱候选的漏检数仍是 5**（占比 4.95% -> 5.05%）；集合只做了小幅换位（kept 7 / only-pre 2 / only-post 4，含命中在内）。
- **严格 sub-stride 的 43 个 GT：`best_iou_weak` 训练前后全部为 0.0000（median / p90 / max 均为 0）**，命中 0 -> 0。
- 新增的 2 个命中都来自 6-8 桶，其中只有 1 个在训练前已被"弱候选"覆盖；命中 4 -> 6、**无任何丢失**。

## 3. 这些证据支持什么、不支持什么

**支持：**
1. 对严格 sub-stride 的目标（43/105），imgsz=1024 的输出里**根本不存在**可用的空间响应（IoU 恒 0），因此"提高阈值以上暴露把弱证据抬过边界"这条路径在物理上无处着力——**空间分辨率/表征瓶颈**。
2. 尺寸是收益的分水岭：仅 6-8 桶对暴露有反应（+540 -> +2），且 6-8 桶恰好是唯一完全高于 stride 的桶。
3. 该瓶颈与 hard-negative 策略无关：V2 与 V3 在 sub-stride 桶的表现完全相同（0 命中、0 弱候选），说明 hard negative 并没有"压掉"这些目标，它们本来就不可定位。

**不支持 / 不能声称：**
1. 不能据此说"tiny 目标无法用 YOLO26s 检测"：本轮只测了 imgsz=1024 与一种暴露干预，未测更高输入尺度、P2、损失加权。
2. 不能把本轮的 recall/mAP 下降（-0.0364 / -0.0509）单独归因于"tiny 暴露有害"：暴露总量 +4.67% 也改变了优化步数与调度位置（设计第 9 节已预注册为混杂因素）；本轮没有做比例消融来分离二者。
3. 不能声称 6-8 桶的暴露路线"有效"：+540 次暴露换 2 个 GT，交换率极低，且伴随 8-16 px 与总体指标的退化。

## 4. 局限（影响结论强度的地方）

1. `val|eth_unseen` 只有 105 个 tiny GT，其中严格 sub-stride 43 个；单一位数变化都会显著改变比例，所以本复盘一律用原始计数叙述。
2. 单种子（seed 42）、单次训练；效应量 -0.0364/-0.0509 未做重复实验估计噪声。
3. `best_iou_weak` 探针的下限是 conf >= 0.01；理论上更低置信度的响应未被观测，但 conf 0.01 已是评估器的 AP 地板量级，实务上等同"无响应"。
4. 判定 `HARMFUL` 是**预注册规则**的机械结果，不应读作"tiny 干预方向错误"：它只说明"在 imgsz=1024 且比例固定的条件下，这 712 次暴露的净效果为负"。

## 5. 给下一步的问题（零训练、可直接检验）

本复盘把问题收敛成一个可判定命题：**在 imgsz 提高后，sub-stride 目标是否开始出现空间响应（best IoU 从 0 变为可定位）？**
这不需要训练，用冻结的 V2 权重在 1024 / 1280 / 1536 上各跑一次即可；判定分支已冻结：

| 观测 | 结论 | 下一实验优先级 |
|---|---|---|
| 1280/1536 让 <4 / 4-6 开始产生候选（IoU 显著 > 0，TP 上升） | 瓶颈是输入尺度而非网格 | **higher-resolution training** |
| 提高输入后 sub-stride 仍基本无响应 | 瓶颈是采样网格本身 | **P2 / stride 4** |
| 只有 6-8 改善、<6 不动 | 两类问题叠加 | **P2 + 6-8 的训练权重策略分开处理** |
